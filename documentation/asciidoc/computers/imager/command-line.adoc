[[command-line]]
== Command-line options

You can launch Imager from the command line with options that change how the graphical interface behaves. You can also run Imager in command-line mode, which writes an image without opening the graphical interface; this is useful for scripting and for provisioning many devices.

On Raspberry Pi OS, the command is `rpi-imager`. On other Linux distributions, run the AppImage instead. To see all available options, run:

[source,console]
----
$ rpi-imager --help
----

[[command-line-gui]]
=== Graphical interface options

[cols="1m,3"]
|===
| Option | Description

| --repo <url-or-file>
| Uses a custom OS list from a URL or a local JSON file. For more information, see <<custom-repositories>>.

| --disable-telemetry
| Turns off anonymous telemetry and saves this setting. For more information, see <<telemetry>>.

| --enable-telemetry
| Clears the saved telemetry setting and restores the default.

| --enable-secure-boot
| Shows the *Secure Boot* customisation subtab for every OS. For more information, see <<customisation-secure-boot>>.

| --enable-language-selection
| Shows the language selection step when Imager starts.

| --qm <file>
| Uses a custom Qt translation (`.qm`) file.

| --debug
| Prints debug messages to the console.

| --log-file <path>
| Writes log output to a file.

| --version
| Prints the version of Imager.
|===

[[command-line-cli]]
=== Write an image from the command line

To write an image without opening the graphical interface, use the `--cli` option. Command-line mode requires root privileges on Linux and Administrator privileges on Windows.

[source,console]
----
$ sudo rpi-imager --cli [options] <image> <device>
----

* `<image>` is the path or URL of the image to write.
* `<device>` is the storage device to write to, for example `/dev/mmcblk0` or `/dev/sdb`.

WARNING: Command-line mode doesn't ask for confirmation before it erases the storage device. Check that `<device>` is correct before you run the command.

Command-line mode supports the following options:

[cols="1m,3"]
|===
| Option | Description

| --sha256 <hash>
| Checks that the image matches the expected SHA-256 hash before writing it.

| --disable-verify
| Skips verification after writing.

| --disable-eject
| Doesn't eject the storage device after verification.

| --first-run-script <file>
| Adds a `firstrun.sh` script to the image.

| --cloudinit-userdata <file>
| Adds a cloud-init `user-data` file to the image.

| --cloudinit-networkconfig <file>
| Adds a cloud-init `network-config` file to the image.

| --secure-boot-key <key-file>
| Signs the boot partition with an RSA 2048-bit private key in PEM format. For more information, see <<customisation-secure-boot>>.

| --cache-file <file>
| Uses a custom cache file. Requires `--sha256`.

| --enable-writing-system-drives
| Allows Imager to write to a system drive. By default, command-line mode refuses to write to system drives. Don't use this option unless you're certain that the destination device is correct.

| --quiet
| Suppresses all console output except errors.

| --debug
| Prints debug messages to the console.

| --log-file <path>
| Writes log output to a file.
|===

For example, to write an image and check its hash:

[source,console]
----
$ sudo rpi-imager --cli --sha256 <hash> raspios.img.xz /dev/sdb
----

To write an image and sign its boot partition for secure boot:

[source,console]
----
$ sudo rpi-imager --cli --secure-boot-key ~/secure-boot-key.pem raspios.img /dev/mmcblk0
----
