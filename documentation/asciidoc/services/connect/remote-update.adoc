== Remotely update your devices

[[remoteupdate-intro]]
Connect can update your Raspberry Pi devices by pushing updates to them remotely. Remote updates are useful for devices that are behind a firewall, physically remote, or hard to reach.

To update a device remotely:

. <<remoteupdate-opt-in,Opt the device in>> to remote updates.
. Build an update artefact: either a <<remoteupdate-otamaker,script artefact>> or an <<remoteupdate-ab,A/B boot update>>.
. <<update-remotely,Deploy the artefact>> from the Connect website, then <<monitor-the-deployment,monitor>> and <<verify-the-deployment,verify>> the deployment.

If your devices belong to a xref:../services/connect-for-organisations.adoc[Connect for Organisations] account, you have more options. An organisation keeps a library of artefacts that you can deploy more than once, and you can host an artefact yourself instead of uploading it, so that the artefact doesn't expire while you wait for a device to come online. For more information, see xref:../services/connect-for-organisations.adoc#deploy-remote-updates[Deploy remote updates in an organisation].

[[remoteupdate-choose-type]]
=== Choose an update type

Connect supports two types of update artefact:

[cols="1,2,2",options="header"]
|===
| | Script artefact | A/B boot update

| What it does
| Runs a shell script as root on the device.
| Replaces the entire operating system.

| Suitable for
| Maintenance tasks, such as upgrading packages, changing configuration, or installing software.
| Complete, versioned operating system images.

| If the update fails
| No automatic recovery. Test your scripts carefully before you deploy them.
| The device automatically reverts to the previous working version.

| Device setup
| Works on a standard installation of Raspberry Pi OS.
| You must first image the device with an A/B boot layout, which needs physical access to the device.

| Supported devices
| Any Raspberry Pi that runs Connect.
| Raspberry Pi 4 and later.

| Build tool
| https://github.com/raspberrypi/utils/tree/master/otamaker[`otamaker`]
| https://github.com/raspberrypi/rpi-image-gen[`rpi-image-gen`]
|===

[[remoteupdate-opt-in]]
=== Opt a device in to or out of remote updates

A device can only receive remote updates if it's opted in. In the Connect website, devices that are opted in show a **Remote update** badge, and a **Deploy** button in the **Devices** tab.

The device must be:

* Connected to the internet.
* Linked to your Connect account and signed in.
* Running the latest version of Connect or Connect Lite, with the `rpi-connect-ota` package installed.

NOTE: If you're setting up an <<remoteupdate-ab,A/B boot update>>, the example image that `rpi-image-gen` builds opts the device in for you, so you can skip this section.

To opt a device in:

. Install or update Connect and the `rpi-connect-ota` package:
+
[source,console]
----
$ sudo apt update
$ sudo apt install rpi-connect rpi-connect-ota
----
+
If you use Connect Lite, install `rpi-connect-lite` instead of `rpi-connect`.
. Opt in to remote updates using the `ota` (over-the-air) subcommand:
+
[source,console]
----
$ rpi-connect ota on
----
+
The command needs superuser rights, so enter your password if prompted. It also restarts Connect, which ends any active screen-sharing or remote shell sessions, including a remote shell you run it from.
. Refresh the **Devices** tab in the Connect website. The **Deploy** button appears next to the device.
+
To check from the device, run <<view-connect-status,`rpi-connect status`>>. The output includes `Remote update: allowed`.

To opt a device out of remote updates, run the following command:

[source,console]
----
$ rpi-connect ota off
----

Like `ota on`, this command asks for your password and restarts Connect, ending any active sessions.

Signing out of Connect doesn't opt a device out. A device stays opted in until you run `rpi-connect ota off`.
